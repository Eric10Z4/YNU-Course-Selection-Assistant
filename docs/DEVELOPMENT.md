# 开发流程

本流程用于把现有 Python 桌面程序逐步扩展到 macOS、安卓和 iOS。项目规则见 [AGENTS.md](../AGENTS.md)，范围及顺序见 [改造计划](ROADMAP.md)，验收场景见 [测试矩阵](TEST_MATRIX.md)。

## 一次改动的工作顺序

1. **明确目标**：描述具体触发条件、预期结果、影响平台和本次不涉及的范围。
2. **读取现状**：检查实现、依赖、构建配置及上次验证证据，不把聊天中的建议当成已完成事实。
3. **消除关键未知项**：先验证会阻塞实现的能力，例如 Mac 原生 WebView、手机 OCR 或后台执行，不提前承诺完整跨平台兼容。
4. **小步实现**：每次解决一个可单独验证的问题；避免在平台验证前大规模重写引擎。
5. **分层验证**：先检查相关逻辑，再做目标系统构建、原生启动和人工交互。网络及状态恢复使用可重复的故障模拟。
6. **审查并上传**：检查改动范围、凭据、文档、回退方式及实际测试结果。用户已授权的常规实现和上传可连续执行。
7. **记录证据**：在 `docs/progress/` 维护阶段记录，并更新 CHANGELOG 与使用说明。

## 记录模板

每个阶段记录目标、基准提交、改动、环境和依赖、执行命令、结果、CI 链接、限制及下一步。状态使用“计划中 / 进行中 / 自动验证通过 / 待人工验收 / 已完成”。

| 证据层 | 可以证明 | 不能据此推断 |
| --- | --- | --- |
| 语法与单元测试 | 解析、指定逻辑和模拟场景可通过 | 目标系统 GUI 可启动 |
| 离线运行检查 | 模型、资源、本机 HTTP 等指定路径可运行 | 真实验证码识别率、学校接口兼容 |
| 原生构建 | 对应架构可以生成应用 | 下载后的 Gatekeeper 体验、全部交互 |
| 原生 GUI 检查 | WebView 加载界面并与本机后端通信 | 文件对话框、锁屏或真实账号功能均已验证 |
| 安卓模拟器检查 | 指定 API/ABI 的模型、桥、任务与服务场景，以及公开包的全新安装启动 | ARM64 实体设备、OEM 省电、长期后台或真实学校业务 |
| 人工与真机验收 | 记录的设备和场景实际通过 | 所有系统版本或所有手机厂商均兼容 |

## 分支与发布

- 新工作使用 `codex/` 前缀分支。远端提交保留当前 main 的历史，不强制覆盖并发修改。
- 验证通过后按授权合入；没有可用验证环境时上传可复查的改动，明确缺失的证据。
- 构建产物通过 CI artifacts 或 Releases 分发，不提交虚拟环境和安装包到 Git。
- 测试包与正式签名发布分别记录。首次 Mac 验证不依赖开发者证书。
- 安卓构建与设备检查按 [安卓指南](ANDROID.md)；公开包从成功的 main 原生运行提取，核对确切提交、固定证书、测试模块排除、构建清单与下载摘要。PR 的临时签名包只作验证。
- 安卓 debug 使用独立 `.debug` 应用 ID 和数据目录；公开包保持应用 ID/预览证书，覆盖更新递增 versionCode。全新安装通过不代表保留数据更新通过；凭据和签名私钥不进入源码或报告。
- 2026-10-25 安卓首个公开预览的证据见 [发布记录](progress/2026-10-25-android-release.md)。当前 P2 是最小适配，公共引擎完整重构未完成；iOS 尚未实现，Mac 付费签名公证按用户选择暂缓。

## Skill 提炼时机

Mac 构建、资源/OCR、本机服务和原生 GUI 检查跑通后，使用 `skill-creator` 把实际有效的阅读顺序、验证命令和状态报告提炼成仓库内的 `ynu-development` skill。

2026-10-21 两种 Mac 架构的上述链路通过后，已创建 [项目 skill](../.agents/skills/ynu-development/SKILL.md)。2026-10-25 在安卓原生模拟器、固定签名公开包检查与发布链路验证后，补充安卓文档路由和恢复/分发边界。打开本仓库后可用 `$ynu-development` 调用；它引用现有文档及脚本，不重新维护命令清单或另一份测试实现。

Skill 只编码稳定、可重复的过程，并链接本项目文档；不复制整份路线图，不把移动端计划写成已验证流程。安装包不能替代真实业务验收。
