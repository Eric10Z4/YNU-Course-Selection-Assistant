# 历史、证据与提交时间

## 重建规则

本仓库从现存文件重建，并非恢复出一个原本存在的 `.git` 目录。更新说明来自相邻版本源码差异；相关 Claude Code 的用户提示历史仅用于核对需求背景，未作为已经实现功能的唯一证据，也没有公开原始对话、会话标识或抓包文件。

1. Windows 历史源码及原打包资料：使用百度网盘对应文件显示的修改日期；所有时间解释为 Asia/Shanghai（UTC+08:00）。这是网盘元数据，可能反映上传或覆盖时间，不能证明最初编辑时刻。
2. Git 作者时间和提交者时间设置为同一个来源时间，精度为秒；多个版本同秒时按版本顺序建立父子关系，不编造时间间隔。
3. Linux：压缩包没有版本号，以网盘压缩包修改时间创建存档提交；压缩包内每个条目的原始时间另见 `zip-entry-times.json`，ZIP 本身不记录时区。
4. `lite_ocr.py`：用户提供的源码包缺少该文件；从相关开发提示指向的旧打包目录找回，以本地原文件修改时间归档。旧目录的 V2.4 主源码与网盘 V2.4 SHA-256 相同。
5. PX10：只有成品，建立明确标注的二进制存档标签，不推断它的源码或功能演进。
6. 本次新写的仓库说明、依赖清单、忽略规则和检查工作流以本次整理时间单独提交，避免伪装为历史文件。
7. GitHub Release 的创建/发布日期由 GitHub 记录为本次迁移日期；历史文件日期写在发布说明中，不混淆二者。

## 文件核对

`file-manifest.json` 记录每个提供文件的 SHA-256、大小、仓库位置或 Release 资产位置与时间来源。原始源码、构建资源、图片、模型、ZIP 与恢复模块均保持字节内容；原始 EXE 以另一个便于下载的英文文件名发布，内容不变。

源码、模型、图片和 ZIP 的本地 MD5 与网盘字段一致。八个大 EXE 的网盘 MD5 字段与本地不一致；BaiduPCS-Go 的[已知问题](https://github.com/qjfoidnh/BaiduPCS-Go#已知问题)说明分片文件可能出现该现象，因此不将该字段当作这八个成品的内容验证证据。本次已逐个读取并解压检查其 PyInstaller 归档结构，并独立计算 SHA-256；这不等于真实业务测试或源码与二进制的可复现性证明。
